## Smoke com o app real

`test_qa_f4_01_smoke.py`: app sobe por `AppFactory` com config YAML e `DependencyContainer` reais; só Mongo/db de
sessões/modelo e o backend de rede do httpcore são falsos. Um run REST chama 4 tools: `cep` (host público: GET sai
pelo IP conferido, `Host` e SNI pelo nome, header por referência resolvido e enviado só a ele), `interno` (host que
resolve para `10.0.0.5`, fora da `TOOL_ROUTE_ALLOWLIST`: recusada na chamada, sem TCP), `rebind` 1ª chamada (ok) e 2ª
(host passa a resolver para metadata: recusada). O modelo recebe "destino recusado pela guarda de rede" sem host nem IP;
resposta HTTP e log (DEBUG, httpcore incluso) sem o segredo; o shutdown fecha o pool.

## Observações (não são bugs; sem ação exigida)

1. **Cliente async compartilhado e event loop.** Reproduzido com servidor loopback real: uma conexão keep-alive aberta
   no loop A e reaproveitada no loop B falha com `RuntimeError: Event loop is closed`. É o comportamento padrão do httpx.
   Em produção há um loop só (`asyncio.run(server.serve())`; as threads de `asyncio.to_thread` usam o cliente
   síncrono). Qualquer script futuro que use o `GuardedHttp`/cliente das tools de dois `asyncio.run` seguidos precisa
   de clientes próprios. Sem teste (fixaria a falha).
2. **Query fixa e parâmetro de mesmo nome.** Se a tool declara um parâmetro com o mesmo nome de uma chave da query fixa
   da `route` (`?tenant=A` + parâmetro `tenant`), o valor do modelo substitui o fixo (`copy_merge_params`). A query fixa
   que não colide é mantida. Decisão de quem escreve a tool; vale registrar na doc de tools.
3. **Log do httpx.** O logger `httpx` (INFO) registra a URL completa do request, inclusive userinfo de route legada
   (`user:pass@host`) e a query com argumentos do modelo. Pré-existe ao F4-01 (a escrita da API admin já recusa
   credencial na route); fica para o F4-03 (auditoria de tool calls) ou para silenciar o logger.
4. **Executor de DNS** é módulo-global e não é encerrado; thread presa em `getaddrinfo` pode atrasar a saída do
   processo até o getaddrinfo desistir (~30 s). Aceito pelo dev e documentado no módulo.

## Lacunas

- **SDK `groq` não instalado**: só se verifica (SDK falso) que a spec entrega o cliente async guardado em
  `client_params.http_client` e que o agno o repassa a `AsyncGroq`; o `TypeError` do caminho síncrono é por analogia
  ao `openai` (mesma geração de SDK), não observado. Cobrir quando `groq` entrar no lock/matriz de versões.
- **TLS real e socket real**: Host/SNI são verificados no `start_tls` do backend falso (nome passado), não com
  certificado; o cross-loop da observação 1 foi só experimento manual (servidor loopback, fora da suíte).
- **Mongo real**: não disponível; o smoke usa os fakes de `tests/fakes/startup_world.py`.
